BOOST CONTROL (wastegate solenoid PWM)  —  code patch, applies to any stock 5JCZ read
UNVERIFIED ON HARDWARE. Bench an ECM first and keep a stock read for recovery.
Source:   boost.s (GNU as -mv850e3v5), build with race/als/build.sh
Apply:    python3 tools/apply_patches.py stock.bin out.bin boost      (re-stamps CRC)
          (or just: apply_patches.py stock.bin race.bin   -> sd + antilag + autoshift + boost)
================================================================================

WHAT IT DOES (rider / tuner view)
 Software-PWMs a RACE-UNUSED output to a boost-control / wastegate solenoid (a MAC-style duty
 valve that bleeds wastegate dome / actuator pressure).
   OPEN LOOP   : solenoid duty = a per-gear feed-forward duty (Duty Gear 1..6).
   CLOSED LOOP : duty = that feed-forward + an integral trim that moves toward a boost TARGET
                 looked up by POWER MODE x GEAR x RPM, from a pressure sensor on a repurposed
                 O2 signal input.
 Below "Min RPM to Run" the solenoid is held off (wastegate spring pressure = least boost).
 Ships DISABLED; all duties and targets 0 (spring pressure). Closed loop ships OFF.

WHY THE O2 CIRCUIT (both halves)
 On a turbo build the stock narrowband O2 sensors are useless under boost and are normally deleted,
 which frees BOTH halves of an O2 circuit:
   OUTPUT - the O2 heater low-side driver becomes the solenoid output.
   INPUT  - the O2 signal input becomes a 0-5 V boost-pressure input for closed loop.
 Air-shift uses the PAIR output; boost uses the O2-heater output; they do not collide.

HOW IT WORKS (code)
 CODE (free flash 0xBE280-0xBE431, 434 bytes, previously 0xFF; right after the air-shifter block):
   BOOST_TICK  runs once per output-mapper cycle (~5 ms), after the stock routine at the second call
               in FUN_5dc9a, so a forced output level has the last word that cycle. Caller-saved regs only.
 HOOK (1):
   0x5DCA2  jarl 0x5DC64  ->  jarl BOOST_TICK   (hook word 86 ff de 05; 0x5DC9E is the air-shifter's)
 INPUTS: rpm fef0258C (confirmed), gear bitmask fef026C2 (confirmed), a boost-pressure ADC on a
   repurposed O2 input (cal "Pressure Input Address", default 0xFEF02648 - CANDIDATE), and the active
   power mode (cal "Mode Input Address", default 0xFEF01F74 = active "PW 1-3").
 RAM: 4 bytes at 0xFEBFE010 (u16 PWM phase + s16 closed-loop trim), above the stack, clear of the
   anti-lag (0xFEBFE000) and air-shift (0xFEBFE008) scratch.

 CALIBRATION SCALARS 0xBF030-0xBF059 (XDF folder "23 Boost Control"):
   +0  u8  Enable             0x80 = on                                   (default 0)
   +1  u8  Bench Test Output  0x80 = hold solenoid asserted               (default 0)
   +2  u8  Closed-Loop Enable 0x80 = trim toward the target table         (default 0 = open loop)
   +3  u8  pad
   +4  u16 PWM Period         task ticks (~5 ms each); duty is 0..Period; def 20 (~10 Hz)
   +6  u16 Min RPM to Run     X/2.56, def ~2000 rpm
   +8  u16 Trim Step          duty ticks per period while closed-loop correcting (clamped +/-Period)
   +10 u16 Pressure Input Addr  low word -> 0xFEF00000+X (def 0x2648)
   +12 u16 Mode Input Addr      low word -> 0xFEF00000+X (def 0x1F74, active PW 1-3)
   +14 u16 Duty Gear 1 .. +24 u16 Duty Gear 6     (per-gear open-loop feed-forward)
   +26 u16 RPM axis[0..7]       target-lookup RPM zone breakpoints, ascending (X/2.56);
                                also the X axis of the Boost Target tables in the XDF.

 CLOSED-LOOP TARGET TABLE 0xBF100 (free flash): u16[3 power modes][6 gears][8 rpm], raw ADC counts.
   Layout: cell(mode,gear,rpm) at 0xBF100 + (mode*48 + gear*8 + rpm)*2.
   Mode A = 0xBF100, Mode B = 0xBF160, Mode C = 0xBF1C0 (96 bytes each).
   Exposed in the XDF as three tables "Boost Target :: Mode A/B/C (gear x RPM)", rows = gear 1-6,
   columns = the shared RPM axis, cells shown in kPa via the sensor transfer. RPM uses the nearest
   lower breakpoint (stepped zones, no interpolation).

*** OUTPUT AND INPUT CHANNELS ARE UNVERIFIED — BENCH THEM FIRST ***
 OUTPUT - OUT_ON / OUT_OFF macros in boost.s. Candidate: O2-heater drive shadow fef020e4 bit0.
          POLARITY IS SET BY THE WIRING (relay coil leg / NO vs NC solenoid), not in software.
          Use "Bench Test Output" to confirm which pin drives the solenoid; if it is a different pin,
          change the address/bit in the macro, re-build (build.sh) and re-apply.
 INPUTS - the pressure and mode channels are cal fields, so point them at whatever the bench proves
          without re-assembling. Closed loop ships OFF so neither is on the critical path until proven.
 BENCH PROCEDURE
   1. Flash a CKTEST/bench bin with the patch applied.
   2. XDF: set "Boost :: Bench Test Output" = 0x80 (leave "Enable" OFF). Confirm the intended
      O2-heater terminal drives the solenoid/relay and nothing else moves. Set it back to 0.
   3. Open loop first: set "Enable" = 0x80, set per-gear Duty, run on a wideband/boost gauge.
   4. For closed loop: feed the pressure input a known voltage, confirm the raw ADC (default
      0xFEF02648) tracks and that "Mode Input Address" reads 1/2/3 as you change ride mode A/B/C;
      set the Boost Target tables (in kPa) and the sensor-transfer equation to match your sensor;
      only then set "Closed-Loop Enable" = 0x80.

NOTES / WATCH
 - A boost solenoid controls boost; it does not protect the engine. Keep a wastegate spring safe at
   0% duty, set per-gear duties and targets conservatively, and log manifold pressure on every pull.
 - DUTY->BOOST DIRECTION depends on your solenoid plumbing (a normally-closed MAC valve bleeding the
   wastegate signal gives more boost with more duty). Confirm and flip the numbers if reversed.
 - Independent of the SD / anti-lag / air-shift patches: no code, cal, RAM or hook overlap.
 - Field 3 (0x1FFEF8) is not recomputed (same as all SD bins). Field-1 CRC is re-stamped by
   apply_patches.py; re-stamp it yourself if you patch inside TunerPro/CalStudio.
