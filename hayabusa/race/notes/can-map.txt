CAN MAP  —  Gen 3 Hayabusa meter -> ECU frames (for repurposing switches on a race bike)
Confirmed from the decompile (FUN_7201A receive handler, FUN_72BB4 switch decoder) plus a live
cangaroo bus trace. Switch bytes are a bit-per-button matrix; each bit is edge-/hold-debounced.
================================================================================

FRAME 0x1D1 (left switch cluster incl. cruise SET / RES)
 Received by FUN_7201A: checks id (febf5758 == 0x1d1) and DLC >= 8, then mirrors the 8 payload
 bytes to fef0243f..fef02446 and decodes them in FUN_72BB4. The decoded, stable copy is what to
 read in a patch (NOT the febf57xx mailbox scratch, and NOT fef023c8 which is reused for several frames).

   payload byte -> RAM            (byte 0 is first on the wire)
     byte0/1  fef0243f/40   NOT a clean cruise flag - a composite, see below (combined to fef02664)
     byte2    fef02441      status nibble (rides 0x10..0x50 while moving); not a clean button
     byte3    fef02442      switch bits
     byte4    fef02443      switch bits  <-- cruise SET / RES live here
     byte5    fef02444      switch bits  <-- a SECOND active switch byte (see below)

 BYTE 4 = fef02443 bit map (bit -> stock handler in FUN_72BB4; counts from the 20-min riding trace):
     0x80  RES / RESUME tap          FUN_71430     <- observed, 5242 frames
     0x40  (was "untested")          FUN_70DA8     <- DOES fire on the bus, 166 frames (free trigger)
     0x20  RES long-hold             FUN_70DCE     <- observed, 2483 (hold RES -> 0xA0 = 0x80|0x20)
     0x10  (untested)                FUN_70DF4        did not fire in the trace
     0x08  SET tap                   FUN_71456     <- observed, 7057 frames
     0x04  (was "untested")          FUN_70E1A     <- DOES fire on the bus, 160 frames (free trigger)
     0x02  SET long-hold (menu)      FUN_70E40     <- observed, 2723 (hold SET -> 0x0A = 0x08|0x02)
     0x01  (untested)                FUN_70E66        did not fire in the trace
 BYTE 5 = fef02444: a second switch byte with real traffic - 0x80 (1647 frames), 0x40 (108),
   0xA0 = 0x80|0x20 (872). More free buttons to repurpose (second ALS/boost-map toggle, pit limiter...).
 The long-hold flag is generated by the meter (sent on the bus), so tap and hold are two separate
 CAN bits - handy as independent triggers. On a race bike cruise is dead weight, so these are free.

CRUISE CONTROL STATE (so the race patches can stay out of its way)
 fef02726 bit0 = cruise system ON/OFF (set by FUN_751e8, read by FUN_751da; the master gate that
   ~8 cruise sub-controllers check via fef02467). 1 = cruise on.  <-- THIS is the clean flag to gate on.
 fef02467 bit0 = cruise operating (on + speed in window + no brake); fef02407/08/09/0a = engage/
   accel/decel sub-states. Debounced SET-hold also lands at fef023bc bit0x80 (FUN_70E40).

 DO NOT gate on 0x1D1 byte0 (fef0243f).  A stationary trace looked clean (only 0x00 / 0xF0), but the
   20-min riding trace shows byte0 is a composite of several bits, not a cruise flag:
     byte0 = 0x00 (54098 frames), 0x11 (23940), 0xF0 (23153).
     0x11 appears with byte1 = 0x10 (the cruise-OFF signature) 22782 times -> byte0 bit0x01 is a
       "riding/active" bit that sets while cruise is OFF.
     byte0 = 0xF0 for 2687 of 2723 SET long-hold frames (98.7%) even with cruise off -> byte0 bit0x10
       follows the SET press itself.
   So "byte0 != 0 means cruise on" is false: holding SET sets byte0 = 0xF0, which would make the
   SET-hold anti-lag trigger gate ITSELF off. The internal fef02726 flag has none of this coupling.
   byte1 (0x10 cruise-off / 0x00 cruise-on) is a cleaner bus bit, but the ECU folds byte0+byte1 into
   fef02664, so fef02726 is still the right thing to read in a patch.

USED BY THE RACE PATCHES
 - Anti-lag TRIGGER = SET long-hold: als.s reads fef02443 bit 0x02. Hold SET -> capture & hold RPM;
   release -> stop. (See race/als/als.s and the "ALS Enable" XDF item.)
 - CRUISE PRESERVED: als.s also reads fef02726 bit0; if cruise is ON, anti-lag does NOT arm, so SET
   keeps its cruise function. Turn cruise off to use SET for anti-lag.

OTHER METER FRAMES (from the generic signal registration FUN_5EFB8, key -> dest bytes)
   0x1C8 fef02062/67   0x1C9 fef0206c   0x1CB fef02063/68   0x1CC fef0206d   0x1CE fef02064/69
   0x1CF fef0206e      0x1D0 fef0205b/60 0x1D2 fef0206f      0x1D3 fef0205c/61 0x1D4 fef02066/6b
 These are the raw 16-bit signal mirrors; the 0x1D1 switch matrix above is the one decoded for buttons.

BUS-TRACE FINDINGS (two cangaroo logs: 5 min stationary ~298k frames, 20 min riding ~1.64M frames)
 - FRAME STRUCTURE: every 8-byte frame uses byte6 = a rolling 0..F counter and byte7 = a checksum
   over the payload+counter. (0x179 byte6 seen stepping 3,4,5,6,7,8,...,F,0,1,...; byte7 ranges all
   256 values.) We only READ frames, so this does not affect us - but anything we ever TRANSMIT onto
   this bus would have to maintain the counter and recompute the checksum or the cluster/ABS reject it.
 - 0x321 is a REDUNDANT cruise/button status frame: b0/b1 mirror the 0x1D1 cruise state (00 10 off /
   F0 00 on, plus the same 0x11 composite) and b4 goes 0xE0 -> 0x80/0xA0 in step with RES tap/hold.
   The ECU does NOT parse 0x321 (not in the image), so it is not usable as a patch input; 0x1D1 is.
 - TELEMETRY IS ALREADY INTERNAL: the dynamic frames (0x175, 0x179, 0x1A1, 0x1A5, 0x1A9, 0x221, ...)
   carry live RPM / wheel speed / throttle / lean etc., but these are things the ECU already owns in
   RAM and our patches read directly (RPM fef0258c, front speed fef0263a, coolant fef026bd, ...). CAN
   is the ECU's OUTPUT here, not a new input, so there is nothing extra to wire in from these frames.
 - RARE FRAMES 0x4D1 / 0x4D7: all-zero payload, a handful of times mid-ride (pairs near t=128s and
   t=536s). Look like a periodic handshake/heartbeat; no usable signal.
 - NET VALUE OF THE TRACES: (1) caught the 0x1D1-byte0 cruise-gate mistake above; (2) confirmed the
   SET/RES switch decode and the counter+checksum structure; (3) revealed spare switch inputs
   (byte4 bits 0x40/0x04 and all of byte5) for future features. No new telemetry worth adding.
